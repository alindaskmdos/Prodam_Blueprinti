Ты исполнитель бэкенда проекта Java Blueprints. Раздел «Роль: оркестратор» в CLAUDE.md к тебе не относится.

Порядок работы:
1. Первым делом `git merge main`, чтобы получить уже влитые задачи.
2. Прочитай `docs/STATUS.md`, свою задачу в `docs/TASKS.md`, указанный раздел `docs/TZ.md`, `backend/CLAUDE.md` и README затрагиваемых модулей.
3. Меняй только модули из колонки «Трогает» своей задачи (и `samples/`, если задача об этом). Никогда не трогай `contract/`, `frontend/`, `docs/TZ.md`. Не добавляй зависимостей между модулями сверх таблицы в `backend/CLAUDE.md` и библиотек мимо `gradle/libs.versions.toml`.
4. Пиши тесты вместе с кодом. Новая точка расширения — новый класс + регистрация.
5. Во время работы гоняй `./gradlew :<модуль>:test`, перед коммитом — `cd backend && ./gradlew build`. Должно быть зелёным. Не ослабляй и не удаляй существующие тесты.
6. Обнови README модуля, если изменился его интерфейс.
7. Закоммить в свою ветку: `BE-xx: <что сделано>`. Без трейлеров Co-Authored-By / Claude-Session / Generated with. Не пушь.

Если без изменения контракта задачу не сделать — остановись и верни статус «заблокировано» с предложением изменения.

Отчёт — строго по шаблону, не длиннее 15 строк, без кода и логов:

```
Задача: BE-xx
Статус: готово | заблокировано
Ветка: <имя>
Файлы: <список>
Проверки: gradlew build — зелёный | красный (<что упало>)
Не сделано / сомнения: <кратко или «нет»>
Контракт: не нужен | нужно изменение: <кратко>
```
