# diagrams

UML проекта с циклами зависимостей (ТЗ §14а.1, §14а.4; отдельной вкладки «Зависимости» нет — решение 2026-10-25, FE-48) во вкладке центральной зоны рядом со «схемой метода». React Flow + ELK (общий воркер `getElk` из editor-nodes). Код — в ленивом чанке: `index.ts` отдаёт только обёртку `UmlTab` (`lazyTabs.tsx`, Suspense), регистрация — `src/app/panels.ts` (`area: 'canvas'`), команда палитры `view.uml`.

- `UmlView` — `GET /projects/{id}/uml` (`useDiagram`, `diagramsStore.ts`: кэш по `projectId#version`, перезагрузка при смене версии, старая диаграмма видна до ответа). Карточка `ClassCard` (FE-44) по умолчанию свёрнута: значок kind (C/I/E/R, без текста-стереотипа), простое имя одной строкой (+ typeParams), пакет мелко второй строкой; высота у всех свёрнутых одна (`CARD.header`). Ширина — по оценке ширины имени (`titleWidth`, замер Inter 700 в Chromium с запасом) и не меньше, чем нужно самой длинной части имени, увеличенной в `FAR_NAME_SCALE` раз. Шеврон «Развернуть» разворачивает только свою карточку, кнопка панели «Развернуть все / Свернуть все» — все: поля `name`, методы `name()` (полная сигнатура в title, клик → схема метода с предзагрузкой), видимость значком + − # ~, конструкторов нет; private скрыты до строки «ещё N private» (компоненты record видны всегда). Список не выше `CARD.maxBody` (9 строк, = max-height `.cardBody`), длиннее — прокрутка внутри; колесо над списком прокручивает его, а не зумит холст (`nowheel`). Уровень (`CardLevel`: compact/expanded/all) меняет размер → новая раскладка ELK по фактическому размеру (развёрнутые карточки не перекрываются), viewport не сбрасывается, развёрнутая карточка остаётся на месте экрана. Отдаление: имя растёт обратно масштабу до `READABLE_NAME_PX` (12) на экране; предел роста один на диаграмму (`nameFit`) — у всех карточек одинаковый экранный размер имени, без многоточия; переносы только по границам camelCase/точке (`nameSegments`); пакет, typeParams и шеврон скрываются, карточка растёт по высоте симметрично. Развёрнутая карточка ниже масштаба `EXPANDED_SCALE_ZOOM` (0.3) показывает только крупное имя.
- Рёбра (`edges.tsx`, `edgeGeometry.ts`): ломаные ELK (POLYLINE, без ортогональных «шин»), UML-маркеры — наследование полый треугольник, реализация пунктир + треугольник, ассоциация стрелка, зависимость пунктир + стрелка, агрегация/композиция полый/залитый ромб у целого; кратность у конца — только у связей наведённой/выбранной карточки (`multiplicitySpot`, вне карточек). `heuristic` — без подписи на ребре: ребро тоньше и бледнее, «эвристика» — в title и легенде. По умолчанию видны только структурные связи; зависимости (`dependency`) — у наведённой карточки (прямой `straightRoute` под карточками, в раскладку не входят) или по переключателю «Все связи» в панели (по умолчанию выкл.; тогда они идут в ELK — `layoutModel`, новая раскладка без сброса viewport). Самосвязь (from === to) — петля справа от карточки (`selfLoopPoints`, не идёт в ELK); связи одного вида между теми же классами сливаются в одно ребро, `via` через запятую. При показанных зависимостях слабые связи «хаба» (≥ 6 исходящих, `hubSources`, напр. Main) до наведения бледные (`edgeFaint`). Ноды передаются с `measured` (размер из раскладки) — иначе Fit View после наведения ждал бы замера.
- Начальный вид (`startView.ts`, как FE-34): если fitView даёт масштаб < 0.6, открывается верх диаграммы в читаемом масштабе, по горизонтали — на самом верхнем узле связной части (классы без видимых связей, которые ELK ставит рядом сверху, не учитываются; вокруг Main), под панелью поиска; Fit View — с полем сверху под панель. Панель сверху слева: поиск (Enter — к первому), Fit View, «Карта», «Все связи», «Развернуть все» (мини-карта 150×96, по умолчанию скрыта, как на холсте метода — FE-37); справа сверху столбиком — «Циклы (N)» (если есть) и сворачиваемая «Обозначения» (легенда с «цикл зависимостей», по умолчанию закрыта).
- `umlGraph.ts` (чистые): `umlToGraph(diagram, levels, cycles)`, `layoutModel(model, showDependencies)`, `alwaysShown`, `cardSize(cls, level)` (= CSS), `titleWidth`, `cardMembers`, `hasMembers`, `nameFit`, `nameScale(zoom, fit, open)`, `nameSegments`, `isStructural`, `visibilityOf`, `matchClasses`, `neighborsOf`, `hubSources`. `umlFlow.ts` — модель + раскладка + наведение/поиск → ноды и рёбра React Flow. `diagramLayout.ts` — `toElk`/`fromElk`/`layoutDiagram`.
- Наведение на карточку подсвечивает её связи, остальное приглушено.
- Переход в редактор (`navigation.ts`): `useFlyTo` — карточка подсвечивается, камера летит к ней (`setCenter` с duration, карточка целиком между панелями; при prefers-reduced-motion — сразу), затем `goToClass(fqn)` — общий выбор класса FE-10 (`selectClass` из project-tree: класс выделен в дереве, форма «Свойства», «Код Java» с прокруткой к span класса; класса нет в дереве — ничего) или `goToMethod` (`selectMethod(UmlMember.id)`, холст — схема метода, Monaco на методе как FE-35). Уход со вкладки/смена проекта во время полёта отменяют переход (cleanup, `onCancel` снимает «занято»). Клик по методу сразу запускает `prefetchMethodBlocks` — GET blocks идёт параллельно с полётом. Выбор проблемы (с blockId) при открытой вкладке UML переключает холст на схему метода (App); выбор проблемы или клик по ноде холста снимает выбор класса (project-tree). `useSelectedClassFqn()` — FQN выбранного класса для подсветки карточки/узла.
- Циклы (FE-48): `useDiagram('deps')` — `GET /projects/{id}/dependencies` в том же кэше по версии; не загрузился — UML без циклов. `cycles.ts` (чистые): `cycleInfo(graph)` (классы циклов и рёбра `inCycle`), `cycleLabel`, `pairKey`. Классы цикла — красная рамка (`cardCycle`, `data-in-cycle`), связи между ними — красные (`DiagramEdgeData.cycle`, маркер `-cycle`) при любом тоне и видны всегда: ребро-зависимость цикла рисуется и идёт в ELK при выключенных «Все связи»; ребро цикла без UML-связи — добавленная `dependency`. Панель «Циклы (N)» (нет циклов — нет панели): наведение выделяет классы цикла, клик → `goToCycleIssue(issueId)` — `selectIssue` без метода/блока, вкладки «Проблемы» и «Код Java». Выбор проблемы CyclicDependency (из панели циклов, анализа, палитры) при открытой UML — классы цикла выделены (пункт панели `aria-current`), камера летит к первому классу; холст не переключается; клик по пустому месту снимает выделение.
