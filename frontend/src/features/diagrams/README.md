# diagrams

Диаграммы проекта (ТЗ §14а.1, §14а.4) во вкладках центральной зоны рядом со «схемой метода». React Flow + ELK (общий воркер `getElk` из editor-nodes). Код — в ленивом чанке: `index.ts` отдаёт только обёртки `UmlTab`, `DependenciesTab` (`lazyTabs.tsx`, Suspense), регистрация — `src/app/panels.ts` (`area: 'canvas'`), команды палитры `view.uml`, `view.dependencies`.

- `UmlView` — `GET /projects/{id}/uml` (`useDiagram`, `diagramsStore.ts`: кэш по `projectId#version`, перезагрузка при смене версии, старая диаграмма видна до ответа). Карточка `ClassCard`: стереотип kind, имя + typeParams, поля «name: Type» (JDK — только текстом), конструкторы, методы; видимость значком + − # ~, static подчёркнут, abstract курсивом. Семантический зум: при масштабе < 0.45 (`semanticScale`) карточка — только стереотип и крупное имя.
- Рёбра (`edges.tsx`, `edgeGeometry.ts`): ломаные ELK (POLYLINE, без ортогональных «шин»), UML-маркеры — наследование полый треугольник, реализация пунктир + треугольник, ассоциация стрелка, зависимость пунктир + стрелка, агрегация/композиция полый/залитый ромб у целого; кратность у конца, `heuristic` — подпись «эвристика». Подписи ставятся вне карточек (`badgeSpot`, `multiplicitySpot`; нет места — без подписи, остаётся title) и видны от масштаба 0.6 или у связей наведённого класса. Самосвязь (from === to) — петля справа от карточки (`selfLoopPoints`, не идёт в ELK); связи одного вида между теми же классами сливаются в одно ребро, `via` через запятую. Слабые (dependency) связи «хаба» (≥ 6 исходящих, `hubSources`, напр. Main) до наведения бледные (`edgeFaint`).
- Начальный вид (`startView.ts`, как FE-34): если fitView даёт масштаб < 0.6, открывается верх диаграммы в читаемом масштабе, по горизонтали — на самом верхнем узле (вокруг Main), под панелью поиска; Fit View — с полем сверху под панель. Панель сверху слева: поиск (Enter — к первому), Fit View, «Карта» (мини-карта 150×96, по умолчанию скрыта, как на холсте метода — FE-37); справа сверху — сворачиваемая «Обозначения» (легенда, по умолчанию закрыта).
- `umlGraph.ts` (чистые): `umlToGraph`, `cardSize` (= CSS), `visibilityOf`, `memberText`, `matchClasses`, `neighborsOf`, `hubSources`, `semanticScale`. `umlFlow.ts` — модель + раскладка + наведение/поиск → ноды и рёбра React Flow. `diagramLayout.ts` — `toElk`/`fromElk`/`layoutDiagram`.
- Наведение на карточку подсвечивает её связи, остальное приглушено.
- Переход в редактор (`navigation.ts`): `useFlyTo` — карточка подсвечивается, камера летит к ней (`setCenter` с duration, карточка целиком между панелями; при prefers-reduced-motion — сразу), затем `goToClass(fqn)` — общий выбор класса FE-10 (`selectClass` из project-tree: класс выделен в дереве, форма «Свойства», «Код Java» с прокруткой к span класса; класса нет в дереве — ничего) или `goToMethod` (`selectMethod(UmlMember.id)`, холст — схема метода, Monaco на методе как FE-35). Уход со вкладки/смена проекта во время полёта отменяют переход (cleanup, `onCancel` снимает «занято»). Клик по методу сразу запускает `prefetchMethodBlocks` — GET blocks идёт параллельно с полётом. Выбор проблемы (с blockId) при открытой вкладке UML/«Зависимости» переключает холст на схему метода (App); выбор проблемы или клик по ноде холста снимает выбор класса (project-tree). `useSelectedClassFqn()` — FQN выбранного класса для подсветки карточки/узла.
- `DependenciesView` (FE-18) — `GET /projects/{id}/dependencies`: узлы — классы (иконка kind, имя, пакет), рёбра «использует» со стрелкой; `inCycle` и узлы циклов — красные (`--jb-severity-high`), связи хабов (кроме циклов) бледные до наведения. `depsGraph.ts` (чистые): `depsToGraph`, `depsFlow`, `cycleLabel`. Список циклов (справа сверху): наведение выделяет классы цикла, клик → `goToCycleIssue(cycles[].issueId)` — `selectIssue` без метода/блока, вкладки «Проблемы» и «Код Java» (файл span проблемы). Клик по узлу — тот же «полёт» и `goToClass(id)`. Тот же начальный вид и кнопка «Карта».

Тесты: `umlGraph.test.ts` (преобразования, слияние via, петли, хабы, подписи вне карточек, семантический зум, начальный вид, раскладка), `UmlView.test.tsx` (MSW `uml.demo.json`: ELK без перекрытий, карточки, клик → стор, отмена полёта при unmount, предзагрузка метода, поиск, версия, ошибка), `DependenciesView.test.tsx` (`dependencies.cycle.json`: циклы красным, список циклов → Issue, клик по узлу; демо без циклов); App.test — проблема при открытой вкладке UML/«Зависимости». Моки: GET uml/dependencies по умолчанию — `uml.demo.json`/`dependencies.demo.json`; `scenarios.dependenciesCycle`, `scenarios.analysisCycle`. `npm test`.
