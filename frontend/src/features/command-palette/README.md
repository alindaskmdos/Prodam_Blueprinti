# command-palette

Командная палитра (ТЗ §14а.14): Ctrl/Cmd+K и Ctrl/Cmd+Shift+P, Esc закрывает, Enter выполняет. Библиотека `cmdk` (только UI и клавиатура; фильтр отключён, `shouldFilter={false}`).

- `CommandPalette({ client, commands, runCommand })` монтируется в `app/App.tsx` (экран редактора). Окно (`PaletteDialog`, cmdk) грузится лениво при первом открытии — основной чанк не растёт. Хоткей ловится в capture-фазе (браузер не перехватывает). Ctrl/Cmd+K не срабатывает, когда фокус в input/textarea/contenteditable (в т.ч. Monaco: аккорды Ctrl+K …, поля диалогов и нод); Ctrl/Cmd+Shift+P глобальный.
- Палитра открывается и поверх модалок (Запуск, Quality Gate, Экспорт); Esc в палитре не всплывает дальше, поэтому закрывается только она.
- Данные: дерево проекта (`useTreeStore`) и анализ (`useAnalysisStore`) — из store. Дерево блоков метода держит внутри себя `BlockSync` (editor-nodes) и наружу не отдаёт, поэтому для группы «Ноды» при открытии палитры делается ещё один существующий GET blocks выбранного метода (новых эндпоинтов нет; можно убрать, если editor-nodes выставит дерево в store).
- `entries.ts` — чистые `buildEntries` / `groupEntries`; группы: Команды, Исправления, Проблемы, Ноды, Методы, Классы, Поля. Пустые группы не рендерятся, «ничего не найдено» не показывается.
- `search.ts` — свой поиск при непустом запросе (`searchEntries`). Score по имени (`PaletteEntry.names`): точное 100 > префикс имени члена/класса 80 > префикс «Класс.член» 75 > подстрока в имени 60 > camelCase-инициалы имени члена 55 («fR» → fullReport; не по «Класс.член») > подстрока в описании (заголовок, hint, keywords) 30. Регистр не важен; несколько слов запроса — все должны совпасть. Совпадения по подпоследовательности букв не показываются никогда. Пункты в группе — по score; группы — по лучшему score, при равенстве навигация (Методы, Классы, Поля, Ноды, Проблемы) выше действий (Команды, Исправления), так что фикс не бывает первым выделенным при не худшем навигационном совпадении. Пустой запрос — `groupEntries` (порядок `GROUP_ORDER`).
- Выбор переиспользует навигацию: метод → `selectMethod` (как клик в дереве); проблема → `selectIssue` (как клик по карточке, FE-05); нода → `setHighlight({source:'canvas'})` (подсветка на схеме и строк в коде); фикс → команда `fix.apply`.
- Класс и поле открывают первый конструктор/метод класса (в контракте нет «выбранного класса»); класс без методов в палитру не попадает.
- Команды — реестр `app/commands.ts`: новая запись появляется в палитре сама; `isEnabled() === false` → пункт неактивен; `paletteHidden: true` скрывает команду с параметрами (`fix.apply` — вместо неё пункты «Применить фикс «…»» по проблемам, неактивные, пока `fix.apply` недоступна).

Тесты: `CommandPalette.test.tsx` — хоткеи, Esc, поиск и навигация (метод, проблема, нода), команды реестра, фикс, ранжирование (`searchEntries`).
