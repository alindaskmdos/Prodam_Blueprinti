# editor-nodes

Схема метода в стиле Blueprints (Graphite): просмотр (FE-03) и правка текста в нодах (FE-07). React Flow (`@xyflow/react`) + ELK.js.

- `<MethodCanvas projectId methodId client? version? onVersion? onMutation? onConflict? />` — грузит `GET .../methods/{methodId}/blocks`, рисует схему и даёт править текст нод. Версия по умолчанию — `useAppStore` (`version` / `setVersion`), пропсы её перекрывают. `onMutation` — `MutationResult` (fileText, tree, analysis) для других панелей, `onConflict` — 409 (холст перезагружается сам). `<MethodGraph view errors? edit? />` — схема для готового `MethodView`; без `edit` — только просмотр. Контейнеру нужна высота.
- Правка (FE-07): двойной клик по тексту ноды или ✎ в заголовке → `NodeTextEditor` — прозрачная textarea поверх подсвеченного `pre` (`highlightJava`, без Monaco), по полю на каждый редактируемый ключ `fields`. Enter / уход фокуса — применить, Shift+Enter — перенос строки (comment, raw), Esc — отмена. 422 → нода красная («· ошибка», сообщение, «Отменить правку»), показывается введённый текст, в код не попало; 409 → тост «Проект изменился» и перезагрузка. Структура не меняется (вставка/удаление — FE-08).
- `blockEdit.ts` — без React: `EDITABLE_FIELDS` / `editableFields(block)` (поля по kind из контракта; method и неизвестный kind не правятся, `case.arrow` сохраняется), путь блока `root/body/1/then/0` (= `GraphNodeData.path`), `blockAt`, `findPathById`, `withFields(root, path, draft)` — иммутабельная замена полей (пустое необязательное поле удаляется).
- `blockSync.ts` — `BlockSync`, логика без React (как `FileSync` в editor-code): GET blocks (+ `GET /projects/{id}` за версией, если её нет); `startEdit/apply/cancelEdit/discardInvalid`; apply → `PUT blocks {version, root}` с полным деревом, в полёте один запрос; 200 → `version` и `method` из ответа; 422 → `invalid {path, draft, errorPath, message}`, нода из `Error.blockId` (не нашлась — правленая), дерево и версия прежние; 409 → `conflict`, версия из `details.serverVersion`, перезагрузка GET blocks и версии; прочее — `error`, редактор остаётся открытым. Внешняя версия новее (`adoptVersion`: правка кода, фикс) → перезагрузка дерева (не только версии, иначе PUT затёр бы чужую правку); при открытом редакторе — `stale`: Enter/blur не отправляют, пометка «Метод изменился» с «Применить к новому» (`rebase`: перезагрузка, нода по id, PUT черновика) и «Отменить». Версия, выросшая во время загрузки, догоняется повторной загрузкой; черновик красной ноды переносится по id. `useBlockSync.ts` — обёртка (`useSyncExternalStore`).
- `blocksToGraph(root, { methodBadge })` — чистая функция: дерево `Block` → ноды/рёбра без координат. Корень `method` — заголовок с бейджем сложности, тело — цепочка сверху вниз. Контейнеры (`if/while/dowhile/for/foreach/switch/case/try/catch`) — group-ноды: заголовок `<id>#head` и ветки. Одна ветка — цепочка прямо в контейнере; несколько — рамки `<id>#slot:<key>` рядом (`да`/`нет`, `try`/`catch`/`finally`). `switch.cases`, `try.catches` — параллельные ветки. Пустые слоты не рисуются. `raw` — пунктирная рамка с исходным текстом, `comment` — стикер. Неизвестный kind (бэк новее типов) — raw-нода с `fields.text`, иначе JSON полей; с непустыми слотами — контейнер, вложенное не теряется. id нод = `Block.id` (нет id — путь в дереве).
- `layoutGraph(graph)` — ELK layered DOWN; в браузере в web worker (`elk-worker.min.js?url`), без Worker (тесты) или если воркер не создаётся — `elk.bundled` в основном потоке. Неудачное создание не кэшируется. Координаты — относительно родительской группы.
- `toFlow(layout)` — ноды/рёбра React Flow: без перетаскивания, соединения, удаления, переподключения рёбер.
- `blocksToGraph(root, { errors })` — ошибки по пути блока: `data.error`, высота ноды с учётом сообщения. В `data` ещё `path`, `fields`, `editable`.
- `kinds.ts` — заголовки, цвета (`--jb-node-*` из `tokens.css`) и слоты по kind; `blockText.ts` — текст ноды из `fields`; `highlightJava.ts` — лёгкая подсветка Java.
- Ноды: `nodes.tsx` (`BlockNode`, `RawNode`, `CommentNode`, `ContainerNode`, `SlotNode`), регистрация — `nodeTypes.ts`; правка приходит в ноды через `NodeEditContext` (`editContext.ts`). `JavaText.tsx` — подсвеченный текст. Стили — `MethodCanvas.module.css`.

Не здесь: сворачивание, мини-карта, переключатель комментариев (FE-06), «+»/удаление/вверх-вниз (FE-08), подсветка строка ↔ нода (FE-05), правка сигнатуры (FE-10).

Тесты: `blocksToGraph.test.ts` (все kind, вложенность, raw, comment, фикстура), `layout.test.ts` (ELK: дети в границах родителя, без перекрытий), `blockText.test.ts`, `MethodCanvas.test.tsx` (MSW на `contract/fixtures/method-view.merge.json`; правка, 422, Esc, 409), `blockEdit.test.ts`, `blockSync.test.ts`. `npm test`.
Моки: PUT blocks по умолчанию (MutationResult из фикстур, `method.root` = присланное дерево), `scenarios.parseErrorOnBlocks` (422 на первую ноду, отличную от фикстуры), `scenarios.conflictOnBlocks`.
