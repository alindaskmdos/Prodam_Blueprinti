# editor-nodes

Схема метода в стиле Blueprints (Graphite): просмотр (FE-03), правка текста в нодах (FE-07), вставка / удаление / вверх-вниз (FE-08). React Flow (`@xyflow/react`) + ELK.js.

- `<MethodCanvas projectId methodId client? version? onVersion? onMutation? onConflict? />` — грузит `GET .../methods/{methodId}/blocks`, рисует схему и даёт править текст нод. Версия по умолчанию — `useAppStore` (`version` / `setVersion`), пропсы её перекрывают. `onMutation` — `MutationResult` (fileText, tree, analysis) для других панелей, `onConflict` — 409 (холст перезагружается сам). `<MethodGraph view errors? edit? />` — схема для готового `MethodView`; без `edit` — только просмотр. Контейнеру нужна высота.
- Правка (FE-07): двойной клик по тексту ноды или ✎ в заголовке → `NodeTextEditor` — прозрачная textarea поверх подсвеченного `pre` (`highlightJava`, без Monaco), по полю на каждый редактируемый ключ `fields`. Enter / уход фокуса — применить, Shift+Enter — перенос строки (comment, raw), Esc — отмена. 422 → нода красная («· ошибка», сообщение, «Отменить правку»), показывается введённый текст, в код не попало; 409 → тост «Проект изменился» и перезагрузка.
- `blockEdit.ts` — без React: `EDITABLE_FIELDS` / `editableFields(block)` (поля по kind из контракта; method и неизвестный kind не правятся, `case.arrow` сохраняется), путь блока `root/body/1/then/0` (= `GraphNodeData.path`), `blockAt`, `findPathById`, `withFields(root, path, draft)` — иммутабельная замена полей (пустое необязательное поле удаляется).
- Структура (FE-08): «+» на стрелках (между соседями, от заголовка к ветке) и ноды «+» в конце каждого слота и в пустых известных слотах (if без else, пустое тело) → меню kind (`InsertMenu`; в `switch.cases` — только case, в `try.catches` — только catch) → новый блок. Есть что вводить — нода появляется локально с открытым редактором (Enter — PUT, Esc — вставка отменяется), break/continue/try — сразу PUT. ↑ ↓ ✕ в заголовке ноды (не у method); Delete / Alt+↑ / Alt+↓ на выделенной (кликом) ноде; удаление контейнера с содержимым — через `confirm`. Стрелки не рисуются и ноды не перетаскиваются.
- `blockTree.ts` — чистые операции без React: `insertBlock(root, {parent, slot, index}, block)`, `removeBlock`, `moveBlock(root, path, ±1)` / `canMove` (только внутри слота, на границе — то же дерево), `templateBlock(kind)` (id `''` — контракт разрешает для новых нод в PUT; обязательные поля пустые, необязательных ключей нет; try — с `catch (Exception e)`), `templateFor(owner, slot, kind)` (новый case — форма arrow соседних case, без соседей — `case X:`), `sameShape`, `insertOptions(owner, slot)`, `nestedCount`. `structureUi.tsx` — `FlowEdge` (тип ребра `flow`), `InsertNode`, `NodeTools`, `InsertMenu`.
- `blockSync.ts` — `BlockSync`, логика без React (как `FileSync` в editor-code): GET blocks (+ `GET /projects/{id}` за версией, если её нет); `startEdit/apply/cancelEdit/discardInvalid`; apply → `PUT blocks {version, root}` с полным деревом, в полёте один запрос; 200 → `version` и `method` из ответа; 422 → `invalid {path, draft, errorPath, message}`, нода из `Error.blockId` (не нашлась — правленая), дерево и версия прежние; 409 → `conflict`, версия из `details.serverVersion`, перезагрузка GET blocks и версии; прочее — `error`, редактор остаётся открытым. Внешняя версия новее (`adoptVersion`: правка кода, фикс) → перезагрузка дерева (не только версии, иначе PUT затёр бы чужую правку); при открытом редакторе — `stale`: Enter/blur не отправляют, пометка «Метод изменился» с «Применить к новому» (`rebase`: перезагрузка, нода по id, PUT черновика) и «Отменить». Версия, выросшая во время загрузки, догоняется повторной загрузкой; черновик красной ноды переносится по id. FE-08: `insert(point, kind)` → `pending` (дерево с новой нодой, `currentRoot(state)`), `remove(path)`, `move(path, delta)` — тот же PUT (version, 409 → перезагрузка); 422 на новую ноду — красная, введённый текст остаётся в `pending`, «Отменить правку» / Esc убирают вставку; 422 на удаление/перестановку — откат, `error` «операция не применена». Пока есть `pending` или stale, структурные операции не выполняются; сначала ждут запрос в полёте и отменяются, если структура за это время изменилась. Перезагрузка (внешняя версия, 409, «Применить к новому») переносит `pending` на новое дерево по id родителя и индексу с введённым текстом; родителя нет — `lostInsert` (текст + «Скопировать»). Выделение ноды сбрасывается при любой смене дерева. `useBlockSync.ts` — обёртка (`useSyncExternalStore`).
- `blocksToGraph(root, { methodBadge })` — чистая функция: дерево `Block` → ноды/рёбра без координат. Корень `method` — заголовок с бейджем сложности, тело — цепочка сверху вниз. Контейнеры (`if/while/dowhile/for/foreach/switch/case/try/catch`) — group-ноды: заголовок `<id>#head` и ветки. Одна ветка — цепочка прямо в контейнере; несколько — рамки `<id>#slot:<key>` рядом (`да`/`нет`, `try`/`catch`/`finally`). `switch.cases`, `try.catches` — параллельные ветки. Пустые слоты не рисуются. `raw` — пунктирная рамка с исходным текстом, `comment` — стикер. Неизвестный kind (бэк новее типов) — raw-нода с `fields.text`, иначе JSON полей; с непустыми слотами — контейнер, вложенное не теряется. id нод = `Block.id` (нет id — путь в дереве).
- `layoutGraph(graph)` — ELK layered DOWN; в браузере в web worker (`elk-worker.min.js?url`), без Worker (тесты) или если воркер не создаётся — `elk.bundled` в основном потоке. Неудачное создание не кэшируется. `getElk()` (общий экземпляр) и `prefersReducedMotion()` экспортируются — их использует `diagrams`. Координаты — относительно родительской группы.
- Раскладка широких вееров (FE-29): если из одного заголовка внутри группы выходит `WIDE_SLOTS_THRESHOLD` (4) и больше рёбер (switch с case; «+»-ноды не считаются, режим правки раскладку не меняет) либо в рамке ветки (`try.catches`) лежит столько же несвязанных веток, группа раскладывается `elk.direction: RIGHT` — заголовок слева, ветки столбцом справа; switch на 16 case остаётся узким и читаемым при fitView. Меньше порога — ветки в строку, как раньше.
- Начальный вид (FE-34, `initialView.ts`): при первом открытии/смене метода `computeInitialView` оценивает масштаб fitView всего метода; если он ниже `MIN_READABLE_ZOOM` (0.5) — вместо fitView открывается верх схемы (нода метода и начало тела) в масштабе от 0.5 до 1 (по ширине вписывается, при нехватке ширины — левый край, иначе по центру) через `defaultViewport`. Иначе — обычный fitView. Центрирование на проблеме (FE-05) приоритетнее; правки вид не трогают; кнопка Fit View в Controls вписывает всё, мини-карта и «Развернуть/Свернуть всё» — для навигации.
- Вид после правки (FE-29): пока считается новая раскладка того же метода (правка текста, «+», удаление, ↑↓, сворачивание), остаётся прежняя схема — `ReactFlow` не пересоздаётся, масштаб и сдвиг сохраняются. Чтобы устаревшие пути нод не применились к новому дереву, на это время правки выключены (двойной клик, «+», Delete, ↑↓, drop из палитры). `fitView` (или центрирование на ноде проблемы) — только при первом открытии метода и смене `methodId`.
- `toFlow(layout)` — ноды/рёбра React Flow: без перетаскивания, соединения, удаления, переподключения рёбер; рёбра типа `flow`, рамки и «+»-ноды без событий мыши.
- `blocksToGraph(root, { insertable: true })` — места вставки: `GraphEdge.insert`, ноды типа `insert` с `data.insert` (`<id>#add:<slot>`).
- `blocksToGraph(root, { errors })` — ошибки по пути блока: `data.error`, высота ноды с учётом сообщения. В `data` ещё `path`, `fields`, `editable`.
- `kinds.ts` — заголовки, цвета (`--jb-node-*` из `tokens.css`) и слоты по kind; `blockText.ts` — текст ноды из `fields`; `highlightJava.ts` — лёгкая подсветка Java.
- Ноды: `nodes.tsx` (`BlockNode`, `RawNode`, `CommentNode`, `ContainerNode`, `SlotNode`), регистрация — `nodeTypes.ts`; правка приходит в ноды через `NodeEditContext` (`editContext.ts`). `JavaText.tsx` — подсвеченный текст. Стили — `MethodCanvas.module.css`.

- Подсветка строка ↔ нода (FE-05): `MethodCanvas` читает `useAppStore().highlight` и `selectedBlockId`. Клик по ноде → `setHighlight({source:'canvas', blockId, span})` (span — `GraphNodeData.span`); `source:'code'` (курсор Monaco) → `blockAtLine(root, line, file)` (самый глубокий блок, `blockLocate.ts`) → рамка `lineHighlight`, в store холст при этом не пишет. Нода `selectedBlockId` пульсирует (`issuePulse`, `jb-pulse`; при prefers-reduced-motion — статичная рамка). `source:'issue'` → центрирование ноды (`focus.ts`: `flowNodeOfBlock` — лист или `#head` контейнера, `centerOnNode` — `setCenter`, масштаб ≥ 1, без анимации при reduced-motion, `useFocusCenter` — один раз на seq; блока ещё нет — после загрузки дерева; первый показ схемы — начальный `fitView` сразу на ноду). Пропсы `MethodGraph`: `highlightBlockId`, `pulseBlockId`, `focus {blockId, seq}`, `onBlockClick`, `onPaneClick`.

- Вид (FE-06) — только клиент, на сервер не уходит (PUT blocks ради сворачивания не шлётся; `Block.collapsed` из контракта — только начальное значение). `collapse.ts` без React: ключ контейнера `blockKey` = `Block.id` (нет — путь), глубина (`containerEntries`: контейнер в теле метода — 1), `defaultCollapsed` = `collapsed === true` или глубина > `COLLAPSE_DEPTH` (3; бэк всегда шлёт `collapsed: false`, поэтому `??` не годится), `collapsedPaths(root, overrides, forcedOpen)` — предки открытого редактора / красной ноды не сворачиваются (`lockedPaths`: шеврон неактивен), `revealKeys(root, blockId, collapsed)` — свёрнутые предки блока, `subtreeIssues`, `blocksLabel`. `viewStore.ts` — zustand `useEditorView`: `showComments` (localStorage `jb.editor.showComments`, try/catch), `collapsed[methodId][key]` — переопределения пользователя; `resetEditorView` для тестов.
- `blocksToGraph(root, { collapsed, collapseLocked, hideComments, keepVisible })`: свёрнутый контейнер — одна нода (id контейнера, тип block/raw) с `data.collapse {key, collapsed, hidden}`: ▸, бейдж «N блоков», бейдж проблем поддерева; без детей и «+» внутри (вставка — после разворота; «+» на стрелках до/после остаются). У заголовка развёрнутого — `data.collapse` с ▾. Скрытые комментарии выпадают только из графа: пути и места вставки остальных — по исходным индексам, ветка из одних комментариев не рисуется, комментарий из `keepVisible` (редактор, ошибка) виден. Дерево и PUT — полные.
- `MethodGraph`: шеврон (`CollapseContext`) и клик по свёрнутой ноде разворачивают; панель вида сверху слева; `MiniMap` (по умолчанию скрыта, FE-37) (цвета по kind из `tokens.css`, контейнеры — контуром). Проблема (`focus`) и строка кода (`highlightBlockId`) внутри свёрнутого → путь разворачивается один раз на цель, затем центрирование FE-05. Выделение скрытой ноды сбрасывается — Delete её не удалит. Смена только вида (то же дерево) не пересоздаёт React Flow — масштаб и сдвиг сохраняются.
- ↑↓ при скрытых комментариях (`canMove` / `moveBlock(root, path, delta, skipComments)`, `BlockSync.move(path, delta, skip)`): блок меняется местами с ближайшим видимым соседом, комментарии остаются на своих местах; за скрытыми комментариями видимого соседа нет — кнопка неактивна.
- Ограничение: состояние сворачивания хранится по `Block.id`, а id позиционный (`…~0/body/1`). Вставка / удаление / ↑↓ выше контейнера сдвигает id, и состояние могло бы перейти к соседу. Поэтому после своих insert / remove / move переопределения контейнеров затронутого слота (с вложенными) сбрасываются (`keysInSlot`, `resetCollapsed`) — они возвращаются к начальному состоянию. Правки извне (Monaco, фикс) состояние не сбрасывают: там сдвиг возможен.

- Палитра (FE-09): `BlockPalette` — кнопка «+ Блок» и раскрывающаяся панель (`role=list`, у элементов `aria-label` / `title`), те же kind, что в меню «+» (`STATEMENT_OPTIONS`; case / catch вставляются только «+»). Нативный HTML5 drag&drop, без зависимостей: элемент палитры тащится на стрелку (или «+» в конце слота) — drop вставляет блок так же, как выбор kind в меню «+» (`NodeEditApi.dropInsert` → `sync.insert`, тот же PUT blocks, новая нода с открытым редактором). Цель под курсором подсвечивается (акцентный цвет стрелки, `data-over` у «+»), только если kind сюда можно (`canDrop`: слот допускает kind, нет неотправленной вставки / stale); drop мимо цели и чужой drag (файл, текст) — ничего. kind держится в модульной переменной `draggedKind` (на dragover `getData` недоступен). Клавиатурная альтернатива — «+» на стрелке. Хук `useDropTarget` — в `structureUi.tsx`.

- Оверлеи без перекрытий (FE-37): сверху слева одна строка — кнопка «+ Блок» (палитра свёрнута по умолчанию, раскрывается выпадающей двухколонной панелью, состояние в localStorage `jb.editor.paletteOpen`) и панель вида («Комментарии», «Развернуть», «Свернуть»). Мини-карта (140×90) скрыта по умолчанию, кнопка ▦ в Controls (`jb.editor.showMinimap`). Занятые оверлеями поля (`Insets`: `TOP_BAR_INSET`, при показанной мини-карте ещё `MINIMAP_INSET`) учитывают начальный вид (`computeInitialView(..., insets)`, `fitViewOptions.padding`) и полёт к блоку проблемы (`centerOnNode(..., area)` центрирует ноду в свободной области). Бейдж сложности в заголовке — с «…» и `title`, заголовок ноды не сжимается.
- Выделение: клик по ноде; Delete / Backspace — то же удаление, что ✕ (`edit.remove`, `confirm` для контейнера; не в поле ввода); Enter — правка текста (`startEdit`, если нода редактируемая); Alt+↑/↓ — перестановка. Рамка выделения (shift+drag) и мультивыбор выключены — групповых действий нет.

Не здесь: правка сигнатуры (FE-10).

FE-43: красная нода — сообщение парсера под кодом отдельным блоком с переносом (`parseError.ts`: `explainParseError` превращает «Found "-", expected one of …» в «неожиданный «-»»; позиция — если в сообщении есть `(line, col)`, список ожидаемого — в `title`, непонятный формат — как есть; высота ноды в `blocksToGraph` считается по разобранному тексту). «!» в заголовке: `title` = `issueTooltip` из `analysis-panel` (русское название правила, серьёзность, message — по каждой проблеме ноды; нет в анализе — название правила из id). FE-24: ИИ-кнопки в заголовке ноды (`AiTools` в `nodes.tsx`, при выборе/наведении) — «Объясни метод» (нода метода) и «ИИ-правка» («Изменить текстом (ИИ)», у любой ноды блока; на ноде метода — весь метод); рисуются только если `/capabilities` разрешает функцию (`features/ai`) и схема редактируемая. Запуск — команды `ai.explain` / `ai.edit` (`blockId` ноды), диалог и применение — `features/ai` (PUT /files только по «Применить»).

FE-49: заголовок ноды всегда в её границах. Кнопки заголовка (▾, ✎, ИИ, ↑ ↓ ✕) — квадраты 18×18; ИИ-кнопки — иконки (облачко «?» — «Объясни метод», искра — «Изменить текстом (ИИ)», aria-label прежние). `headerWidth(data, edit)` в `blocksToGraph.ts` — минимальная ширина под название, бейджи и кнопки (в режиме правки — ✎, ИИ, ↑ ↓ ✕, они место занимают и невидимыми); ширина ноды для ELK = max(оценка по тексту, `headerWidth`). Запас на случай ошибки оценки: сначала сжимается бейдж сложности, затем название с «…». Тест: `blocksToGraph.test.ts` (FE-49).
