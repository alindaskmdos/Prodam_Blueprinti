# Журнал решений

Формат: что решили — почему. Новые решения дописывает оркестратор по команде человека.

## Продукт

- **Бэкенд на Java + JavaParser с Symbol Solver** — нужны типы (ArrayList.contains vs HashSet.contains), печать кода обратно и компиляция из JVM.
- **Метод = дерево блоков, выражения — текст** — round-trip всегда валиден, граф всегда компилируется; в 5 раз проще деревьев выражений.
- **Блок `raw` для неподдержанного** — код никогда не теряется.
- **Источник правды — текст кода** — одна точка истины, неизменённые методы байт в байт.
- **Редактор: React Flow, структурная схема в стиле Blueprints (B+C)** — совпадает с концептом слайда 4; стрелки не рисуются, чтобы не было неструктурированных графов. Страховка: режим «только просмотр».
- **Комментарии — отдельная нода** — пользователь может добавлять их визуально; комментарии в конце строки переезжают на отдельную строку, внутри выражений — теряются.
- **Классы/поля/сигнатуры — формы в дереве проекта**, блок-схема только для тел методов.
- **Невалидный текст ноды не попадает в код** — проверка parseExpression/parseStatement.
- **LLM необязателен** — продукт полностью работает без ключа; LLM — опциональный провайдер.

- **Gradle, многомодульный монолит; Spring только в `app`** — границы модулей охраняет компилятор (агент не может их «удобно» нарушить), модули совпадают с колонкой «Трогает» в задачах, тесты модулей без Spring-контекста быстрые. Spring Modulith отклонён: границы проверялись бы только тестом.

## Загрузка

- **`.java`, `.zip`, `.jar` только с исходниками; `.class` → отказ** — продукт работает с исходным кодом, декомпиляция теряет комментарии и имена и даёт пользователю «чужой» код. Декомпиляция — позже, отдельной кнопкой.
- **Защита от zip slip и zip bomb** — архив от пользователя недоверенный.
- **Source root по `package`, а не по раскладке; у файла `path` и `package`** — любая раскладка работает, экспорт возвращает исходную структуру.
- **Несовпадение пакета и папки — предупреждение; дубликат FQN — отказ** — первое компилируется, второе нет.
- **Экспорт: .zip с исходниками и исполняемый .jar в обязательном минимуме** — .jar закрывает шаг «Собрать Java» со слайда 3 и стоит дёшево. Собирается только из чистого кода: переписывания для запуска (seed, видимость, счётчики) изменили бы поведение программы пользователя.

## Анализ

- **Сложность по нескольким символам (n, m)** — O(n·m) ≠ O(n²); иначе ложные тревоги.
- **Символы размера через копии и параметры** — `new ArrayList<>(a)`, `List.copyOf`, `b = a`, stream-filter → тот же символ; внутри метода + параметры, без полей (поля — позже).
- **Неуверенные выводы → вкладка «Предупреждения» («Возможно…»), без автофикса.**
- **Оценка — порядок операций, не коэффициент ускорения** — Big O не учитывает константы; «в X раз» только после замера по кнопке.

## Проверка поведения

- **Сравнение: stdout побайтово + exit code + тип и сообщение исключения, без stack trace** — номера строк меняются при любом рефакторинге.
- **Фиксы сохраняют порядок перебора (Linked*)** — иначе меняется вывод.
- **Недетерминизм: seed для Random при запуске + двойной прогон оригинала, шумные строки маскируются**; >50% шума → предупреждение.
- **Тесты редактируемые: IO (original/manual) + JUnit в MVP** — пользователь сам определяет «поведение совпадает».
- **Нет stdin-тестов при чтении System.in → зелёный статус заблокирован.**
- **Тестов нет вовсе → `incomplete` (жёлтый, не блокирует) + конструктивная подсказка**: «Тестов пока нет — проверена компиляция. Добавьте IO-тест (можно сохранить из запуска), и каждое изменение будет подтверждаться автоматически». Не «поведение не проверено»: предупреждаем и подсказываем, что делать. Quality Gate применяет фикс с пометкой «подтверждена компиляция, тестов нет».
- **Один Docker-контейнер на весь прогон проверки** (текущая версия + оригинал, все тесты) — контейнер на каждый тест × двойной прогон давал десятки секунд на кнопку.
- **Manual-тест, «починенный» правкой** (оригинал не проходит, текущая проходит) → `passed` + пояснение в `error`; оригинал прогоняется для всех manual-тестов — без изменения контракта (`TestStatus` — одно значение).
- **JUnit: private→package-private только при сборке тестов; «не компилируется» — отдельный статус.**
- **Пропущенный JUnit-тест (@Disabled, assumption) → `passed` + «пропущен» в `error`; BE-10 добавляет в `VerifyResult.warnings` «N тестов пропущено»** — без изменения контракта, вердикт не блокируется одним @Disabled.

## Объём

- **2 человека, без сокращений ради JUnit**; буфер — список «Позже» и режим «только просмотр» для нод.
- **Refactoring, декомпозиция, граф вызовов, LLM, замер — позже**, но точки расширения закладываются сразу.

## Если успеем

- **Список и порядок «если успеем» — в ТЗ §14; берутся только после работающего обязательного пути.** Остальные идеи — `docs/IDEAS.md`.
- **Подсветка синтаксиса в нодах — в обязательном минимуме** — дёшево, заметно.
- **PMD вместо SonarQube** — Sonar требует отдельный сервер с Elasticsearch, гигабайты памяти и байткод; PMD — библиотека, работает за секунды, конфиг редактируется в UI. Sonar — в идеях.
- **Агрегация/композиция в UML — эвристика с пометкой** — это смысл, а не синтаксис.
- **Покрытие и debug — на одной инструментации** (`Trace.hit` / `Trace.value` в копии для запуска).
- **WebSocket — только для интерактивной консоли**; синхронизация остаётся REST + версия.
- **Автодополнение по таблице символов, без языкового сервера.**
- **Командная палитра — только фронт, на уже загруженных данных; действия UI сразу регистрируются в `commands.ts`** — тогда палитра в конце не требует переделки кнопок.
- **Пользовательские шаблоны и конфиг PMD хранятся в проекте (`.blueprints/`)** — экспортируются вместе с кодом; при экспорте галочка, по умолчанию включена.
- **PMD без правил, пересекающихся с нашими детекторами** — иначе дубли карточек.
- **Мёртвый код: main, переопределения, методы Object/Comparable и вызовы из tests/ — используемые; уверенно только приватное и недостижимое.**
- **Циклы: без пары внешний↔вложенный; 2 класса — низкая, 3+ — средняя серьёзность.**
- **UML: связи только между классами проекта, коллекции → связь к T с кратностью *.**
- **Инструментация: числовые индексы в long[], пакет `__blueprints`, после super/this, запись в shutdown-hook, таймаут ×3** — иначе O(n²)-программа не укладывается в таймаут или код не компилируется.
- **Проверка поведения всегда на чистом коде; покрытие — отдельный прогон по кнопке.**
- **Debug: один тест, 10 000 шагов, объекты без toString()** — toString может менять состояние.
- **Шаблоны: обязательные заполнители и суффиксы занятых имён.**
- **Консоль: тот же код с seed, одна на сессию.**
- **ИИ: лимиты запросов на сервере; правка ноды текстом — через дифф и кнопку.**
- **Автодополнение: таблица символов на метод целиком, фильтрация на фронте.**
- **Что из «если успеем» показывать на демо и когда останавливать разработку — решает человек; агенты и документы этого не регулируют.**

## Командная работа

- **Каждый владеет своей папкой; общая зона только `contract/`, меняется по решению людей.**
- **Contract-first + MSW-моки** — фронт не ждёт бэк.
- **Один оркестратор на человека, код пишут субагенты в worktree, ≤3 исполнителя параллельно на разных пакетах** — скорость без конфликтов; лимиты использования общие.
- **verifier и reviewer без права записи** — исполнитель не может «починить тест».
- **Оркестратор вливает в локальный main, push делает человек.**
- **Без атрибуции ИИ в коммитах** — settings `attribution` + правило в CLAUDE.md + проверка в verifier. Git-хук `commit-msg` убран из репозитория по решению человека; при появлении трейлеров добавляется вручную.
- **Состояние живёт в STATUS.md, не в контексте** — /clear каждые ~5 задач.
- **Arrow-switch в блоках (CT, 2026-10-23)** — `case.fields.arrow="true"` вместо raw: `case X ->` — обычный код Java 21 и встречается в корпусе. label хранит метку текстом, поэтому паттерны и `when` тоже поддержаны. Тело стрелки — слот body.
- **BE-05: третий круг ревью (2026-10-23)** — решение человека после двух красных ревью подряд: вернуть тому же исполнителю (Jackson из model убрать, текст выражений из TokenRange, строгий тест комментариев).
- **Локальные enum/interface (2026-10-23)** — JavaParser 3.26.2 их не разбирает. В начале BE-06 пробуем свежий JavaParser; если не помогает — файл, который не парсится, грузится как текст без блоков (код не теряется, загрузка не падает).
- **.gitattributes с LF (2026-10-23)** — решение человека: рабочие файлы всегда с LF (кроме *.bat/*.cmd), чтобы IO-тесты (.out) и round-trip «байт в байт» не зависели от core.autocrlf на Windows. Касается и frontend/ — напарнику сообщено. На уже склонированных Windows-копиях файлы перевыписать один раз.
- **command-job через файл-скрипт (2026-10-23)** — на Windows ProcessBuilder ломал argv со встроенными кавычками для docker.exe; Runner пишет команду в /app/jobs/<k>.sh (read-only, аргументы в одинарных кавычках) и запускает `sh` этого файла.
- **blockId у проблем анализа (2026-10-23)** — решение человека: `analysis` (без зависимости от `blocks`) отдаёт проблему с диапазоном строк, `blockId` подставляет `app` по совпадению диапазона с блоками. Контракт и граф модулей не меняются.
- **BE-06: зона расширена на `source` (2026-10-24)** — решение человека: запасной путь для локальных enum/interface (не разбирает и JavaParser 3.28.2) живёт в `source`: файл, который разбирает javac, грузится текстом без блоков; если не разбирает и javac — PARSE_ERROR.
- **UNPARSED_FILE в LoadWarning.code (2026-10-24)** — решение человека: отдельный код для файла, загруженного текстом без блоков (IGNORED_FILE означает «проигнорирован»). Фронту — перегенерировать типы.
- **Замена тела метода по смещениям токенов (2026-10-24)** — решение человека вместо LexicalPreservingPrinter: остальной файл не трогается вообще, LPP ненадёжен на Java 21. Правило в backend/CLAUDE.md обновлено.
- **Комментарии в BlocksToJava (2026-10-24)** — решение человека после двух красных ревью: комментарии выводятся в исходном виде без экранирования; новый/изменённый комментарий с `\u` → UnsafeCommentException (в BE-07 — 400), а не попытка экранировать.
- **BE-14: нераспознанное число итераций не понижает confidence (2026-10-24)** — решение человека (отступление от §8.2): поиск по списку линеен в любом случае. Fresh-размер списка, связанный с символами окружающих циклов, тоже не понижает; несвязанный → low.
- **BE-15: третий круг ревью (2026-10-24)** — решение человека после двух красных ревью подряд: вернуть тому же исполнителю (элемент цикла «дешёвый» только без промежуточных неконстантных циклов; стоимость целиком из fresh → low, а не молчание).
- **BE-15: четвёртый круг ревью (2026-10-24)** — решение человека: вернуть тому же исполнителю одно замечание (правило «метод со скалярными параметрами — нераспознанные циклы дешёвые» глушило N+1 вида findById(int) с перебором репозитория).
- **BE-17: тело метода — уровень вложенности 1 (2026-10-24)** — решение человека: так maxNesting совпадает с contract/fixtures/analysis.merge.json (merge = 4) без правки контракта; порог DeepNesting > 4. LongMethod > 50 строк (при 40 срабатывал плоский switch Main.dispatch).
- **BE-38: контракт тестов/запуска (2026-10-24)** — решение человека: у PUT/DELETE tests/{name} обязательный `version` и ответ 409; у run/verify ответ 503 (песочница недоступна); у verify 422 (AMBIGUOUS_MAIN, INVALID_REQUEST); пара .in/.out — везде mode `manual` (так её реально гоняет IoTestSource).
- **BE-20: демо фикса LinkedHashSet (2026-10-24)** — фикс ужесточён (параметры/поля при сторонних вызовах в цикле не берутся), в demo ни одна находка не подходит. Решение человека: не ослаблять фикс, а добавить в samples/demo безопасное место (локальный список из `new` в том же методе) — задача BE-41.
- **Фиксы правят текст по диапазонам, не LexicalPreservingPrinter (2026-10-24)** — решение человека: BE-19/BE-20 меняют только нужные диапазоны исходника (неизменённое байт в байт, перевод строки сохраняется) — это строже LPP. Правило backend/CLAUDE.md для фиксов считать выполненным.
- **BE-20: третий и четвёртый круги ревью (2026-10-24)** — решения человека после красных ревью подряд: вернуть тому же исполнителю (3-й: `reversed` в VIEWS; 4-й: `descendingIterator` у LinkedList и сверка всех методов ArrayList/LinkedList, возвращающих изменяемое представление).
- **BE-21: третий круг ревью (2026-10-24)** — решение человека после двух красных ревью подряд: вернуть тому же исполнителю (поиск наследников/анонимных подклассов T и своих List должен охватывать tests/*.java).
- **BE-24: только уверенные находки мёртвого кода (2026-10-24)** — решение человека: неприватные методы не сообщать (на demo давали 14 low-находок шума во вкладке предупреждений и issueCount). Остаются приватные методы без вызовов, неиспользуемые локальные, код после return/throw/break/continue/yield.
- **CT-01: id фикса в analysis.merge.json (2026-10-24)** — решение человека: `index-by-key` → `index-by-id` (как регистрирует BE-21); тесты фронта AnalysisPanel/gate поправлены тем же коммитом с разрешения человека.
